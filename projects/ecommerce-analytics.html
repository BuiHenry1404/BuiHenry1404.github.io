Analytics agent for an e-commerce business

E-commerce platform · FPT Software · Jun – Sep 2026

A multi-agent system for an e-commerce company that runs its own online platform. The sales lead and the accountant ask about revenue and cost in plain language, and a chain of agents answers from the sales database and builds full reports with charts and slides. It is used every day at the client.

The problem

All the sales and invoice data was already in the database, but getting answers out of it was slow. When the sales lead or the accountant needed numbers, an analyst had to pull the data together by hand and build a report — about three days of work each time. Any new question meant waiting for the next report.

What it does

For a quick question — the sales lead asks about revenue by day, month or year, the accountant asks about cost — a single agent answers in the chat through SQL tools.

A full report is more work, so it runs as a chain of agents that hand work to each other: one lists the invoices and aggregates them by month, the next builds the report, another writes it up, and a last one turns it into presentation slides.

report request → aggregate invoices → build report → write-up → slides

I was the only engineer on the AI and backend side, in a team of four (the others were a tester, a project manager and a business analyst).

Keeping the numbers correct

Numbers have to be exact, so the AI does not write its own SQL. It can only call tools with SQL written in advance — for example, list the invoices for a day or a month, or total a month's revenue. Every number in an answer comes straight from the database through one of these tools, not from the model.

The agent can still pick a wrong number, so code checks every figure in an answer against the database. If a figure does not match, the code sends the error back to the model, which calls the tool again with corrected parameters — up to three times. Each tool checks the caller’s user ID and role and drops itself when the role is not allowed, so the sales lead sees revenue and the accountant sees cost — access enforced in code, not just the prompt.

To check how well it did, I built an eval set of 250 questions across 12 months of real data, and compared the agent's answers with the reports the company already had for those months. The agent answered about 90% of them correctly.
