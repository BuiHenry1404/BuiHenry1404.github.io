Multi-agent analytics for an e-commerce business

E-commerce platform · FPT Software · Jun – Sep 2026

A multi-agent system for an e-commerce company that runs its own online platform. The sales lead, the accountant and the warehouse manager ask for numbers in plain language; an orchestrator and four specialist agents fetch the data, analyse it, check it and turn it into a report with charts and slides. It is used every day at the client.

The problem

All the sales data already existed, but getting answers out of it was slow. For every report an analyst pulled the data together by hand, which took about three days, and any new question had to wait for the next report.

Architecture: an orchestrator and four agents

For a quick question, the orchestrator sends it straight to the agent that can answer it. A full report runs through the whole chain, and every agent passes structured output to the next instead of free text:

request → Orchestrator: execution plan → Retrieval → Analysis → Validation → Report
  • Orchestrator. Reads the request (for example "revenue report for October"), works out the goal and the period (01/10–31/10), writes an execution plan as JSON and assigns the other agents.
  • Retrieval. Fetches the numbers through the sales API: this month, last month, and the split by region. It returns structured data with its source.
  • Analysis. Computes growth against the previous month, each region's share, and which regions rose or fell.
  • Validation. Checks the result before anyone sees it (below).
  • Report. Writes the text, draws charts with matplotlib and builds slides with python-pptx, then exports PDF, Excel and PowerPoint.

What the Retrieval agent hands to Analysis:

{
  "period": "2026-10",
  "total_revenue": 1500000000,
  "currency": "VND",
  "regions": [
    {"name": "North", "revenue": 600000000},
    {"name": "South", "revenue": 900000000}
  ],
  "source": "sales_database"
}

Self-correcting validation

Numbers in a management report have to be right, so a dedicated Validation agent checks every report before it is built: the totals add up, the growth maths is correct, the text says the same thing as the numbers, and no data is missing. It returns pass or fail with a list of problems.

Validation: fail → orchestrator finds which agent caused it → that agent redoes its step → Validation again

The orchestrator does not restart the whole run; it traces the error back to the agent that caused it and asks only that agent to redo its step. After up to 3 retries, if the problem is still there, the workflow stops and tells the user instead of sending a wrong report.

RBAC at the agent level

Each agent checks the caller's role, and an agent is removed from the run when that role is not allowed to use it. The sales lead sees revenue, the accountant sees cost, and the warehouse manager can only ask for stock reports, never revenue. A new role can be added without changing the agents.

How accuracy was measured

I built an eval set of 329 questions across 12 months of real data and graded the system's answers against the reports the company already had for those months. It answered about 90% of them correctly.
